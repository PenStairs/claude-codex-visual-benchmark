# Runners

A runner is the CLI agent harness that turns a model profile into a coding agent inside a participant workspace. `scripts/lib/runners.mjs` is the registry; every runner module exports the same surface (`buildArguments`, `buildResumeArguments`, `parseSessionId`, `parseUsage`, `credentialStatus`, `isSubscriptionBacked`, `doctorChecks`, `selfTest`, `selfTestParsers`, `runAgent`). The orchestrator never branches on a runner name; it calls `getRunner(model)`.

| runner | CLI | native login | metered / third-party | protocol |
| --- | --- | --- | --- | --- |
| `codex` | Codex CLI (`codex exec`) | `codex-login` (ChatGPT subscription) | `environment` key + `provider.baseUrl` | OpenAI Responses / Chat Completions |
| `claude` | Claude Code (`claude -p`) | `claude-login` (Claude Pro/Max subscription) | `environment` key + `provider.baseUrl` | Anthropic Messages |

A subscription login only works inside its own CLI. A ChatGPT subscription cannot drive the `claude` runner and a Claude subscription cannot drive the `codex` runner; to run GPT models under Claude Code you would need an OpenAI API key plus an Anthropic-compatible translation gateway, which this skill deliberately does not bundle.

## Codex runner

Unchanged from the original skill: `codex exec --ignore-user-config --ignore-rules --strict-config --skip-git-repo-check --json --approve-for-me -C <workspace> -m <model> -c model_reasoning_effort=... [provider -c overrides] -` with the prompt on stdin. Later rounds use `codex exec ... resume <thread_id> -`. Session ids come from `thread.started`; usage from `turn.completed`.

## Claude runner

Round 1:

```text
claude -p --output-format stream-json --verbose --model <model>
       --permission-mode bypassPermissions --permission-prompts none
       --setting-sources project --strict-mcp-config --disable-slash-commands --no-chrome
       --disallowedTools WebFetch,WebSearch [--effort <preset>]
       --session-id <uuid generated by the benchmark>
```

Later creative rounds and repair rounds replace `--session-id <uuid>` with `--resume <uuid>` and run from the same workspace (Claude Code stores sessions per working directory). The prompt is passed on stdin. The `system/init` event must echo the requested session id; the final `result` event supplies `modelUsage`, `num_turns`, `duration_api_ms`, and a CLI list-price cost estimate. For first-party Anthropic profiles, the final report prefers that list-price estimate because it preserves cache-pricing detail omitted by the normalized token schema. It is still not a settled charge.

Isolation choices and why:

- `--setting-sources project` drops the user's `~/.claude/settings.json` (hooks, permissions, MCP servers, env). The workspace has no `.claude/` directory, so nothing else loads.
- `--strict-mcp-config` with no `--mcp-config` means zero MCP servers. `--disable-slash-commands` removes user skills. `--no-chrome` removes the browser bridge.
- `WebFetch` and `WebSearch` are disallowed so that the "no network services" rule is enforced by the harness, matching the verification policy that rejects remote URLs in generated code.
- User memory (`~/.claude/CLAUDE.md`) is outside the settings system and is still loaded. `doctor` warns when it is non-empty; keep it empty or benchmark-neutral during runs.
- The launch environment strips `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL`, the `ANTHROPIC_DEFAULT_*_MODEL` overrides, Bedrock/Vertex/Foundry switches, effort/thinking overrides, and `CLAUDE_CONFIG_DIR`, then sets only what the profile declares. A `claude-login` profile therefore always uses the native login even if the shell exports an API key.
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `DISABLE_AUTOUPDATER=1`, `DISABLE_TELEMETRY=1`, and `DISABLE_ERROR_REPORTING=1` keep the process quiet and deterministic. `API_TIMEOUT_MS` defaults to 600000 and can be raised per profile with `runnerOptions.apiTimeoutMs` for slow third-party models.

Reasoning presets: `reasoning.control` is `effort-flag` when Claude Code should pass `--effort <low|medium|high|xhigh|max>`, or `none` when the endpoint cannot accept an explicit effort control. The bundled first-party and verified DeepSeek/GLM Anthropic-compatible profiles use `effort-flag`; Flash defaults to `max`, while non-Flash defaults to `high`. A future profile using `none` must expose a single honest preset such as `provider-default`.

Third-party Anthropic-compatible profiles (`provider.wireApi: "anthropic"`) receive `ANTHROPIC_BASE_URL`, the key as `ANTHROPIC_AUTH_TOKEN` (or `ANTHROPIC_API_KEY` when `authentication.header` is `x-api-key`), and every Claude Code model role (`ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL`) pinned to the benchmark model so no hidden helper call reaches the provider with an unknown model id.

## Preflight and fail-fast

Before any paid generation starts, `run` calls each runner's `preflight(model)`. The Claude runner makes one low-effort, few-token call (`claude -p --output-format json --tools "" --no-session-persistence --model <model> --effort low`) that surfaces an expired OAuth token (401), a Claude Code build too old for the model (400), a model the account cannot use (404), quota exhaustion (429), or an unreachable third-party endpoint. The outcome and reported usage are written to `runs/<id>/preflight.json`. Plain `doctor` performs static/local CLI, login, flag, model-catalog, and configuration checks only; `doctor --probe-models` explicitly opts into the paid Claude model probe. The Codex runner returns `null` for preflight because there is no equivalent cheap real call.

Creative and repair rounds run both participants in parallel under one `AbortController`. When one participant's process fails (non-zero exit, API error, generation timeout), the other participant's process is sent SIGTERM immediately and its phase is recorded with `aborted: true`. The run report still names the participant that failed first; the aborted side is not a model failure.

Generation uses the same lifecycle on both sides: a 3600-second soft warning that does not terminate the agent, a 10800-second hard stop, a 900-second no-output stop, and a 60-second heartbeat. Each heartbeat is printed to stderr and appended to `model-<side>/logs/progress.jsonl`, with elapsed/idle time and the runner's best available thinking-token, tool-call, and file-write counts. Timeout reports distinguish `hard-timeout`, `idle-timeout`, and `peer-aborted`. Repairs reuse the participant's generation preset (`max` for Flash, `high` otherwise), allow two rounds, and have a 3600-second limit per round.

The orchestrator does not add an outer automatic retry around paid runner calls; native CLI transport retries remain intact. If one participant failed for infrastructure reasons after the other completed all creative rounds, `describe-retry` plus `retry-participant` provides a user-confirmed clean retry of that side and labels the resulting report `recovered-single-participant`.

## Usage schema

Both runners normalize to:

```text
input_tokens            every prompt token, cached or not
cached_input_tokens     prompt tokens served from cache
cache_write_input_tokens
output_tokens           includes reasoning tokens
reasoning_output_tokens Codex: reasoning_output_tokens; Claude: thinkingTokens
uncached_input_tokens   = input_tokens - cached_input_tokens
total_tokens            = input_tokens + output_tokens
reasoning_tokens_reported, source, runner, event_count, complete
estimated_cost_usd      Claude Code list-price estimate or null (used for first-party Anthropic list-price output; never a settled charge)
```

`self-test` feeds equivalent probes through both parsers and fails if the totals disagree.

## Windows notes

Claude Code's native installer provides `claude.exe`; the npm package provides `claude.cmd`. `scripts/lib/process.mjs` prefers a native executable and otherwise launches the npm CLI through Node directly (no shell). The same rule already applied to `codex.cmd` and `npm.cmd`.

## Adding a runner

Create `scripts/lib/<runner>.mjs` with the exported surface above, register it in `runners.mjs`, add its native login type to `NATIVE_LOGIN_TYPES` in `config.mjs` if it has one, and extend `self-test` probes so that the shared usage schema stays consistent. A future neutral API-level runner (one harness for every model) fits the same interface.
